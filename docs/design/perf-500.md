# 500 页文档性能实测

## 2. 引擎基准（主进程外，直接 NodeCompiler）

`npm run perf:500`：

| 指标                              | 耗时 / 大小         |
| --------------------------------- | ------------------- |
| 编译器创建（含系统字体）          | 37.4 ms             |
| 冷编译（首次 502 页）             | 334.1 ms            |
| 同内容二次编译（缓存）            | 6.3 ms              |
| 增量编译（改 1 段后 `mapShadow`） | 110.3 ms            |
| vector artifact                   | 2,096,352 B         |
| PDF 导出                          | 161.8 ms（2.60 MB） |

结论：编译本身不是瓶颈；500 页冷编译约 0.33 s、增量约 0.11 s。

## 3. 应用内实测

探针：`DECKLE_PERF_PROJECT=perf/500-pages npm start`，主进程 `attachPerfProbe` 用 `executeJavaScript` 驱动，单次运行：

| 指标                              | 耗时    | 说明                        |
| --------------------------------- | ------- | --------------------------- |
| 打开项目（读文件 + 建 store）     | 104 ms  | 1.5 MB 文件                 |
| 编译就绪（自打开项目起）          | 166 ms  | 含一次缓存命中              |
| 首屏第一页 canvas                 | 157 ms  | 编译后开始渲染              |
| 编辑 1 字符 → 新 artifact         | 710 ms  | 含 400 ms 防抖，净约 310 ms |
| 滚到文档中部（第 250 页附近）出图 | 275 ms  | 懒渲染触发                  |
| 已渲染页 / 总页                   | 8 / 502 | IntersectionObserver 虚拟化 |
| DOM 节点数                        | 2,223   | 占位页 + 已渲染页           |
| JS 堆                             | 84 MB   | 含编辑器、渲染器、artifact  |

## 4. 分析

1. **打开与首屏**：104 ms 打开、166 ms 编译就绪、157 ms 首屏出图，500 页文档“可感知启动”约 0.4 s，符合预期。
2. **编辑延迟**：710 ms 中含 400 ms 防抖，净编译+重渲染约 310 ms。长文档可把防抖降到 250 ms，压到约 0.55 s。
3. **滚动**：虚拟化后只渲染 8 页、DOM 2,223 节点；滚到中部 275 ms 出图，内存 84 MB，未随页数线性增长。
4. **依赖图表的发现**：dev 环境的 CSP（`default-src 'self' 'unsafe-inline' data:`）没有放行 `blob:`，渲染器加载图片时被拦截，WASM 在 `vec2canvas` 里 panic，含图页永远空白。已在 `forge.config.mjs` 的 `devContentSecurityPolicy` 中放行 `blob:`（default-src / img-src / connect-src），修好后第 250 页（含图）正常渲染。
5. **未测项**：583k 字符在 CM6 的逐键输入延迟、撤销栈内存、多文件项目（几十个 `chapter.typ`）的编译增量，留到 M6 用同一探针扩展。

## 5. 复现

```powershell
npm run perf:500
$env:DECKLE_PERF_PROJECT = "D:\Code\Deckle\perf\500-pages"
npm start
```

探针结果输出到控制台 `[perf:500]`；引擎基准原始数据在 `perf/500-pages/report.json`。

## 6. 后续建议（按收益排序）

1. 长文档自适应防抖：文档 > 200k 字符时 `armCompile(250)`。
2. 相邻页预取：滚动停止后预渲染上下各 1 页，减少 275 ms 的空白。
3. 输入延迟专项：测量 `keydown → 屏幕更新`，必要时把高亮/折叠改成 `ViewPlugin` 增量计算。
4. M6 再评估 `utilityProcess`：目前主线程编译 334 ms 冷启动会卡一次窗口；若后续文档更大再迁移。
5. 多文件项目基准：拆成 50 个章节文件，测 watcher + 增量编译 + 文件树刷新。
